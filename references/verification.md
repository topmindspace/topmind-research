# 内容审查核实机制（强制门）

两个子技能的任何输出在交付前必须通过本机制。未通过不得交付。

## 一、来源分级

| 级别 | 定义 | 例子 |
|---|---|---|
| T0 | 一手来源 | 公司官网公告、官方 blog、论文原文、财报、system cards |
| T1 | 权威二手 | Reuters、AP、官方通讯社 |
| T2 | 行业媒体 | 机器之心、量子位、TechCrunch、The Verge（以其注明的一手出处为准） |
| T3 | 传闻/自媒体 | X 爆料、匿名消息、"据悉"类——只作线索，不作定论 |

## 二、核实规则

1. **关键事实**（人名、数字、日期、结论性判断）必须 ≥2 个独立来源交叉，其中至少 1 个是 T0/T1。
2. **一手优先**：能找到 T0 就不用 T1/T2 转述；引用 T2 时必须同时给出它引用的 T0 链接。
3. **厂商口径**：公司自称的数据、排名、"首个/最强"类表述，一律标注"厂商口径"，不做事实陈述。
4. **无法核实**：删掉，或明确标注"未核实/传闻"，不许写成肯定语气。
5. **时效戳**：每条信息标注获取时间；研究结论标注"截至 XXXX-XX-XX"。
6. **译名**：人名、产品名以官方为准；官方无中文名时保留英文原名，不自造译名。
   - 教训（2026-10-07）：Kenso Soai 曾被误写为"曾素海"，正确为硤合憲三（Soai Kensō）。存疑时宁可只写英文。
7. **数字**：金额、参数、日期换算单位后复核一遍；百分比说明基数。

## 三、发布前自检清单

- [ ] 关键事实都有 ≥2 独立来源且至少 1 个 T0/T1
- [ ] 厂商口径已标注
- [ ] 未核实内容已删除或明确标注
- [ ] 时间戳/截至日期已写
- [ ] 译名无自造
- [ ] 来源链接可打开（抽查）

## 四、纠错

交付后发现事实错误：立即更正并记录到 CHANGELOG，下游引用（记忆/专题/已发快讯）同步修正。

## 五、隐私保护

1. 只收录**公开**信息源与公开人物动态；不收录、不传播私人联系方式、住址等非公开个人信息。
2. 引用截图/转述时做脱敏：隐藏无关人员的姓名、头像、联系方式。
3. 输出不包含用户的隐私信息；用户主动提供的私人资料仅用于本次研究，不沉淀、不外传。
4. 信息源配置（`config/sources.yaml`）中不得出现任何密钥、token、私有 API 地址。
