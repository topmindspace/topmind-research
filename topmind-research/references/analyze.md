# analyze · 深度研究

围绕一个明确问题，读一手资料、做对比、给出带来源与置信度的结论。研究和写作分开：先把资料收齐、核清，再一次性写报告。

## 1. 研究简报

按 `assets/templates/research-brief.md` 写简报，至少包含：

- 要回答的问题（一到三个，能判断答没答上）
- 范围与时间窗（截至哪天，哪些版本）
- 对比口径（版本、测试集、日期；不是对比类写「不适用」）
- 交付形式（研究报告 / 事实表 / 两者）
- 投入档位（见第 2 节）

问题不清就先问用户，不要猜。用户直接给了论文或报告链接、问题也明确时，简报可以只写在状态文件里，不必等确认。

**需要用户确认后才开始的情况**：投入档位是「综述」，或预计要起 4 个以上子 agent。把简报和计划发给用户，用户改完或同意后再执行（同 Gemini Deep Research 的计划确认做法）。

## 2. 定投入

| 档位 | 例子 | 子 agent | 工具调用 |
|---|---|---|---|
| 单点 | 「X 模型的上下文长度是多少」「这篇论文的主要结论」 | 不起 | 3–10 次 |
| 对比 | 「A 和 B 的架构差异」 | 每个对象 1 个，2–4 个 | 每个 10–15 次 |
| 综述 | 「MoE 最近半年进展」 | 按子题分工，最多 6 个 | 先报计划，确认后再跑 |

档位判定：

- 对象是 1 个具体产品、1 篇论文或 1 个数字 → 单点。
- 对象是 2–4 个点名的具体产品或论文 → 对比。
- 对象是一类东西（「开源模型」「Agent 框架」）、或超过 4 个对象、或时间跨度超过 3 个月的进展 → 综述。
- 例：「开源权重模型和闭源模型在编程基准上的差距」对象是两类模型，判综述，先报计划；用户在计划里收窄到 2–4 个具体模型后改按对比执行。

硬线：

- 任意时刻并行子 agent 不超过 6 个，多了分批。
- 子 agent 不得再派子 agent。给子 agent 的任务描述里不要写「可以继续拆分 / 可以调用 agent 工具」。
- 宿主不支持子 agent 时按同样的分工串行执行。

## 3. 检索

1. **先宽后窄**：先用短查询看全貌，再逐步收窄；不要一上来就写很长很具体的查询。
2. **一手源优先**：先找论文原文、官方技术报告、system card、官方博客、官方仓库，精读其中 3–5 篇最关键的；二手解读只用来找线索。
3. **多视角提问**（对比、综述档位）：计划阶段列 3–5 个视角（技术、成本、开发者体验、商业、监管，按题目选），每个视角写 2–3 个要查的问题，再分给子 agent。
4. **给子 agent 的任务描述**必须包含四项：目标问题、输出格式、优先使用的信源与工具、边界（不查什么、什么时候停）。
5. **子 agent 回传**：只回传清洗后的要点，每条附来源（URL、发布日期、级别）和原文摘录（≤2 句）；内容多时写入状态目录下的文件，只回传文件路径。

## 4. 反思补洞

每轮汇总后列出：

- 还没回答的问题
- 来源之间的矛盾
- 只有 T2/T3 支撑的关键结论

有就针对性补检索，最多补 2 轮。2 轮后仍未解决的，写进报告「局限与待核」，不要硬凑结论。

## 5. 写作

研究全部结束后，按 `assets/templates/analyze-report.md` 一次写完，不要让多个子 agent 分头写章节再拼接。

- 结论先行，每个结论标置信度（高 / 中 / 低，定义见 `references/input-guide.md`）。
- 章节按论证组织，标题写判断（如「开源模型的差距主要在长上下文」），不写检索维度（如「性能对比」）。
- 表格用于参数、价格等需要反复查的数据；论证用段落。
- 对比类写明口径；口径不一致的数据不放进同一张表。
- 写完自检：核心结论如果拿给业内人看没有任何可争议之处，说明结论太泛，回到第 4 步找更具体的判断；但不能为了「有观点」牺牲证据要求。

## 6. 核验

强制过 `references/verification.md`：逐句 `[n]` 引用、引用支撑检查、核验记录。论文以原文为准；数据回到一手出处；厂商自称数据标「厂商口径」。

## 7. 交付与沉淀

1. 交付研究报告；需要出稿时同时产出 `assets/templates/fact-sheet.md` 格式的事实表。
2. 落盘位置、记忆建议、信源候选按 `references/upgrade-rules.md` 的「沉淀」处理，全部是建议，用户确认后执行。

## 状态文件

每完成一步，把进度写入 `references/state.md` 指定位置的状态文件（简报、计划、已完成子题、来源表、待办）。中断后从状态文件继续，不重复已完成的检索。

## 铁律

- 不编造数据，不补写原文没有的内容；不确定的写「原文未提及」。
- 对比必须说明口径（时间 / 版本 / 测试集），口径不一致不硬比。
- 写明资料发布时间，研究结论标注「截至 YYYY-MM-DD」。
